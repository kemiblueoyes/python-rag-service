The glossary defines terms used throughout the Python RAG Service and its documentation.

## A

### Answer evaluation

Evaluation of generated answers against expected answer behavior. In the Python RAG Service, automated checks evaluate evidence sufficiency and citation behavior, while human review evaluates support, completeness, unsupported details, and focus.

**Related terms:** [Citation validation](#citation-validation), [Evaluation dataset](#evaluation-dataset), [Generated answer](#generated-answer), [Grounded answer](#grounded-answer), [Sufficient evidence](#sufficient-evidence), [Unsupported claim](#unsupported-claim)

## B

### BM25 retrieval

The lexical retrieval method used by the Python RAG Service to find chunks based on words and other textual matches in the query. It searches the lexical corpus using the BM25 ranking algorithm.

**Related terms:** [Candidate chunk](#candidate-chunk), [Hybrid retrieval](#hybrid-retrieval), [Lexical corpus](#lexical-corpus), [Retrieval](#retrieval)

## C

### Candidate chunk

A chunk being considered during retrieval before the pipeline has finished selecting the results to return. Vector retrieval and BM25 retrieval each produce ranked lists of candidate chunks.

**Related terms:** [Chunk](#chunk), [Reciprocal rank fusion (RRF)](#reciprocal-rank-fusion-rrf), [Reranking](#reranking), [Retrieval](#retrieval), [Retrieved chunk](#retrieved-chunk)

### Canonical document

The platform-neutral document representation used by the Python RAG Service after content is retrieved from a source. It gives later indexing stages a consistent structure that doesn't depend on the original content system.

#### Example

The WordPress connector maps a WordPress page into a canonical document containing fields such as its document ID, title, URL, body, content type, and source metadata.

**Related terms:** [Chunking](#chunking), [Connector](#connector), [Content source](#content-source)

### Chunk

A smaller, retrieval-ready unit of content created from a canonical document. A chunk keeps enough document and heading information to preserve where the content came from.

#### Example

One documentation page can produce several chunks, each containing text from a section of the page along with its document ID, heading path, URL, and other metadata.

**Related terms:** [Canonical document](#canonical-document), [Chunking](#chunking), [Retrieval](#retrieval)

### Chunking

The process of splitting document content into smaller units that can be indexed and retrieved independently. The Python RAG Service uses document structure, including headings, to help preserve useful context in each chunk.

#### Example

A documentation page with several sections can be divided into separate chunks while keeping each chunk associated with its section heading and source document.

**Related terms:** [Canonical document](#canonical-document), [Chunk](#chunk)

### Citation validation

The application-side check that verifies that citation identifiers in a generated answer refer to chunks that were actually supplied in the language model's context. It also verifies that their source metadata comes  from those trusted retrieved chunks.

#### Example

If the language model cites S1, citation validation confirms that S1 was included in the context supplied for that request before the answer is returned.

**Related terms:** [Context](#context), [Generated answer](#generated-answer), [Grounded answer](#grounded-answer), [Retrieved chunk](#retrieved-chunk)

### Client

An application that sends requests to the Python RAG Service API and uses the responses it returns.

#### Example

The included WordPress client sends Search and Ask requests to the RAG service and displays the returned search results, answers, and sources.

**Related terms:** [Connector](#connector)

### Connector

Code that retrieves content from a content source and maps source-specific data into the Python RAG Service's canonical document model.

#### Example

The WordPress connector retrieves published WordPress content and maps each record into a canonical document.

**Related terms:** [Canonical document](#canonical-document), [Content source](#content-source)

### Content source

A system that supplies documentation to the Python RAG Service for indexing. WordPress is the current content source. Other content systems can be supported through additional connectors.

#### Example

A WordPress site is a content source. The WordPress connector retrieves its published content and maps it into canonical documents.

**Related terms:** [Canonical document](#canonical-document), [Connector](#connector)

### Context

The retrieved chunks selected and assembled for the language model (LLM) to use when generating an answer. Context is what the model receives. Not every part of the context necessarily supports the final answer.

**Related terms:** [Evidence](#evidence), [Generated answer](#generated-answer), [Retrieved chunk](#retrieved-chunk)

## E

### Embedding

A numeric representation of text that allows the retrieval system to compare text by meaning. The Python RAG Service creates embeddings for indexed chunks and for incoming queries.

#### Example

During indexing, Voyage creates an embedding for each chunk. During retrieval, the service creates an embedding for the query and compares it with the stored chunk embeddings.

**Related terms:** [Chunk](#chunk), [Vector retrieval](#vector-retrieval)

### Evaluation dataset

A maintained collection of test cases used to measure retrieval or answer quality against defined expectations. In the Python RAG Service, the evaluation dataset is versioned so results can be tied to the exact cases and expectations used for a run.

**Related terms:** [Answer evaluation](#answer-evaluation), [Retrieval evaluation](#retrieval-evaluation)

### Evidence

Information in the retrieved context that supports an answer to the user's question. Evidence is different from context because context can include retrieved information that the answer doesn't use.

**Related terms:** [Context](#context), [Grounded answer](#grounded-answer), [Insufficient evidence](#insufficient-evidence), [Sufficient evidence](#sufficient-evidence)

### Expected-empty

An evaluation outcome where retrieval is expected to return no chunks because the indexed documentation doesn't contain an adequate answer to the query.

#### Example

A test case asking about information that's not documented can be marked expected-empty so the case passes only when retrieval returns no chunks.

**Related terms:** [Retrieval](#retrieval), [Retrieval evaluation](#retrieval-evaluation), [Support gate](#support-gate)

## G

### Generated answer

An answer produced by the language model (LLM) from the supplied context. A generated answer becomes a grounded answer only when the application's evidence and citation checks required by the Python RAG Service succeed.

**Related terms:** [Citation validation](#citation-validation), [Context](#context), [Grounded answer](#grounded-answer)

### Grounded answer

An answer generated from retrieved documentation and supported by the evidence supplied to the language model (LLM). In the Python RAG Service, a grounded answer also passes the required evidence-sufficiency and citation validation checks before it's returned.

**Related terms:** [Citation validation](#citation-validation), [Evidence](#evidence), [Generated answer](#generated-answer), [Sufficient evidence](#sufficient-evidence)

## H

### Hybrid retrieval

The retrieval approach used by the Python RAG Service that combines vector retrieval and BM25 retrieval. The two methods produce separate candidate lists that are combined with reciprocal rank fusion before reranking.

#### Example

A chunk missed by vector retrieval can still become a candidate through BM25 retrieval, and a chunk found by both methods can receive a stronger fused rank.

**Related terms:** [BM25 retrieval](#bm25-retrieval), [Reciprocal rank fusion (RRF)](#reciprocal-rank-fusion-rrf), [Reranking](#reranking), [Retrieval](#retrieval), [Vector retrieval](#vector-retrieval)

## I

### Indexing

The process of turning source content into retrieval-ready data. In the Python RAG Service, indexing includes retrieving source content, mapping it to canonical documents, creating chunks and embeddings, and storing the data used by retrieval.

#### Example

Indexing a WordPress site retrieves its published content, creates canonical documents and chunks, generates embeddings, and stores the resulting retrieval data.

**Related terms:** [Canonical document](#canonical-document), [Chunking](#chunking), [Connector](#connector), [Content source](#content-source), [Embedding](#embedding)

### Insufficient evidence

A condition where the retrieved context doesn't contain enough information to support a grounded answer. This can happen even when relevant chunks were retrieved.

#### Example

Retrieval may find documentation about the right topic while still missing the information needed to answer the specific question.

**Related terms:** [Evidence](#evidence), [Relevance](#relevance), [Sufficient evidence](#sufficient-evidence), [Support](#support)

## L

### Lexical corpus

The collection of indexed chunk text used for lexical retrieval. In the Python RAG Service, the lexical corpus is stored in data/wordpress-chunks.json and is used to build the in-memory BM25 index.

#### Example

After indexing WordPress content, the service writes the current chunks to the lexical corpus so BM25 retrieval can search them by words and other textual matches.

**Related terms:** [BM25 retrieval](#bm25-retrieval), [Chunk](#chunk), [Indexing](#indexing)

## P

### Precision

The proportion of evaluated retrieval results that are judged relevant to the query. In the Python RAG Service, Precision@5 measures precision across up to the first five returned chunks.

#### Example

If four of five evaluated results are relevant, Precision@5 is 0.8.

**Related terms:** [Recall](#recall), [Relevance](#relevance), [Retrieval evaluation](#retrieval-evaluation)

## R

### Recall

The proportion of the known relevant sources for a test case that retrieval successfully finds. In the Python RAG Service, Recall@5 measures how much of the expected relevant content appears in up to the first five returned chunks.

#### Example

If a test case defines four relevant sources and retrieval finds three of them in the evaluated results, Recall@5 is 0.75.

**Related terms:** [Precision](#precision), [Relevance](#relevance), [Retrieval evaluation](#retrieval-evaluation)

### Reciprocal rank

A retrieval metric based on the position of the first expected primary source in the ranked results. The score is 1 divided by that result's rank, so finding a primary source earlier produces a higher score.

#### Example

If the first primary source appears at rank 2, the reciprocal rank is 0.5.

**Related terms:** [Reciprocal rank fusion (RRF)](#reciprocal-rank-fusion-rrf), [Retrieval evaluation](#retrieval-evaluation)

### Reciprocal rank fusion (RRF)

A method for combining multiple ranked result lists using each candidate's position in those lists rather than comparing their raw scores. The Python RAG Service uses RRF to combine the vector and BM25 candidate lists.

#### Example

A chunk that ranks well in both vector retrieval and BM25 retrieval receives contributions from both lists and can move higher in the fused ranking.

**Related terms:** [Candidate chunk](#candidate-chunk), [Hybrid retrieval](#hybrid-retrieval), [Reranking](#reranking)

### Relevance

How closely content relates to a query. Relevant content can be useful for the topic without containing enough information to answer the question.

**Related terms:** [Retrieval](#retrieval), [Support](#support)

### Reranking

A second-stage retrieval step that scores a smaller set of candidate chunks against the query and puts them into a new relevance order. In the Python RAG Service, reranking happens after reciprocal rank fusion.

**Related terms:** [Candidate chunk](#candidate-chunk), [Hybrid retrieval](#hybrid-retrieval), [Reciprocal rank fusion (RRF)](#reciprocal-rank-fusion-rrf), [Relevance](#relevance), [Support gate](#support-gate)

### Retrieval

The process of finding content that's relevant to a query. In the Python RAG Service, retrieval combines vector retrieval and BM25 retrieval, then applies fusion, reranking, and the support gate to select the chunks returned to search or answer generation.

**Related terms:** [BM25 retrieval](#bm25-retrieval), [Hybrid retrieval](#hybrid-retrieval), [Reranking](#reranking), [Retrieved chunk](#retrieved-chunk), [Support gate](#support-gate), [Vector retrieval](#vector-retrieval)

### Retrieval evaluation

Evaluation of whether the retrieval pipeline returns the expected chunks for a set of test cases. The Python RAG Service measures retrieval quality using relevance judgments, expected-empty behavior, precision, recall, and reciprocal rank.

**Related terms:** [Evaluation dataset](#evaluation-dataset), [Expected-empty](#expected-empty), [Precision](#precision), [Recall](#recall), [Reciprocal rank](#reciprocal-rank), [Retrieval](#retrieval)

### Retrieval-augmented generation (RAG)

An approach that retrieves relevant information from an external source and provides it to a language model (LLM) as context for generating a response. In the Python RAG Service, retrieved documentation chunks provide the context used to generate grounded answers.

**Related terms:** [Context](#context), [Grounded answer](#grounded-answer), [Retrieval](#retrieval)

### Retrieved chunk

A chunk that remains after the retrieval pipeline has selected the content to return or use as evidence. For POST /v1/search, retrieved chunks become search results. For POST /v1/answer, they're passed to answer generation.

**Related terms:** [Candidate chunk](#candidate-chunk), [Chunk](#chunk), [Context](#context), [Retrieval](#retrieval), [Support gate](#support-gate)

## S

### Sufficient evidence

Retrieved evidence that contains enough information to support a grounded answer to the user's question.

#### Example

If the retrieved chunks contain the information needed to answer the question and the answer-generation checks succeed, the response can report sufficient_evidence as true.

**Related terms:** [Evidence](#evidence), [Grounded answer](#grounded-answer), [Insufficient evidence](#insufficient-evidence), [Support](#support)

### Support

Whether retrieved content contains enough information to answer the user's question. Support is different from relevance: content can be relevant to a topic without adequately answering the query.

**Related terms:** [Relevance](#relevance), [Retrieved chunk](#retrieved-chunk), [Support gate](#support-gate)

### Support gate

The retrieval decision that determines whether the reranked candidates adequately support returning results for a query. In the Python RAG Service, the gate checks the highest reranking score against the configured support cutoff and returns no chunks when the requirement isn't met or when reranking returns no chunks.

#### Example

A query can retrieve topically relevant candidates but still return no search results when the support gate determines that the candidates don't adequately support the query.

**Related terms:** [Relevance](#relevance), [Reranking](#reranking), [Retrieved chunk](#retrieved-chunk), [Support](#support)

## U

### Unsupported claim

A statement in a generated answer that's not supported by the retrieved evidence. An unsupported claim is an answer-quality problem, not the same thing as an unsupported user query.

**Related terms:** [Citation validation](#citation-validation), [Evidence](#evidence), [Generated answer](#generated-answer), [Grounded answer](#grounded-answer)

## V

### Vector retrieval

A retrieval method that compares an embedding of the query with stored chunk embeddings to find chunks with similar meaning. In the Python RAG Service, vector retrieval searches the embeddings stored in Qdrant.

#### Example

A query can retrieve a relevant chunk even when the query and chunk use different words for the same idea.

**Related terms:** [Candidate chunk](#candidate-chunk), [Embedding](#embedding), [Hybrid retrieval](#hybrid-retrieval), [Retrieval](#retrieval)
