Look up supported configuration settings for the Python RAG Service.
Each entry lists the setting, its type, whether you must set it, the default, accepted values, and what it controls.

**`Required`** indicates no default value and you must provide a value for the stated capability to work.
If a usable default exists, you don't need to set the value unless you want to change the default.

For the setup procedure, see [Configure the service](/docs/get-started/configure-the-service).

## API and authentication

The service uses one shared API key. Clients send it on search and answer requests.

| Setting | Type | Required | Default | Accepted values | Description |
| --- | --- | --- | --- | --- | --- |
| `RAG_API_KEY` | string | Yes, for the API to start | none | A non-empty string | Clients send this value in the `X-API-Key` header. The API requires a non-empty value before it starts. `GET /health` doesn't check the key. If search or answer receives a request while the key is unset, the route returns `503` with `authentication_unavailable`. |

## Embedding

Indexing and search turn text into vectors with Voyage. These settings choose the model, the vector size,
the request batch size, and the API key.

| Setting | Type | Required | Default | Accepted values | Description |
| --- | --- | --- | --- | --- | --- |
| `EMBEDDING_PROVIDER` | string | No | `voyage` | `voyage` | Selects the embedding provider. `voyage` is the only supported value. |
| `EMBEDDING_MODEL` | string | No | `voyage-4-lite` | A Voyage model name | Selects the Voyage model used to create document and query embeddings. |
| `EMBEDDING_DIMENSION` | integer | No | `1024` | An integer of at least 1 that matches the model output | Sets the vector size stored in Qdrant. Use the output dimension of `EMBEDDING_MODEL`. The default `voyage-4-lite` configuration uses 1,024 dimensions. Startup rejects a value below 1. It doesn't call Voyage to compare the dimension with the model. |
| `EMBEDDING_BATCH_SIZE` | integer | No | `128` | An integer of at least 1 | Sets how many texts the indexing command sends to Voyage in one embedding request. |
| `VOYAGE_API_KEY` | string | Yes, for the API to start | none | A non-empty Voyage API key | Authenticates Voyage embedding and reranking requests. The API requires a non-empty value before it starts. Startup doesn't call Voyage. |

## Vector database

Indexed chunks and their vectors are stored in Qdrant. These settings choose the instance, the collection name,
and the API key when the instance requires one.

| Setting | Type | Required | Default | Accepted values | Description |
| --- | --- | --- | --- | --- | --- |
| `VECTOR_DATABASE` | string | No | `qdrant` | `qdrant` | Selects the vector database. `qdrant` is the only supported value. |
| `QDRANT_URL` | string | No | `http://localhost:6333` | An `http` or `https` URL with a host. A port, when present, is an integer from 1 through 65535. | Sets the URL of the Qdrant instance. `localhost`, an IP address, and a hosted name are valid, such as `http://localhost:6333` or `https://your-cluster.cloud.qdrant.io`. Startup checks that syntax locally. It doesn't resolve the host or contact Qdrant, and the log doesn't include the URL. |
| `QDRANT_API_KEY` | string | No, unless the Qdrant instance requires an API key | none | A Qdrant API key, or empty | Authenticates requests to Qdrant. Leave unset for an unauthenticated local instance. Set it when you enable API-key authentication locally or connect to a remote instance that requires a key.|
| `QDRANT_COLLECTION` | string | No | `rag_chunks` | A collection name | Names the Qdrant collection that stores indexed chunks and their vectors. The service creates the collection. |

## Content source

Indexing reads content from a WordPress site. These settings choose the site, the REST path, request limits, the
post types to retrieve, and the connector profile.

| Setting | Type | Required | Default | Accepted values | Description |
| --- | --- | --- | --- | --- | --- |
| `WORDPRESS_BASE_URL` | string | Yes, for indexing | none | A WordPress site URL | Sets the site the WordPress connector reads. Indexing stops when this value is empty. |
| `WORDPRESS_API_PATH` | string | No | `/wp-json/wp/v2` | A REST API path | Sets the REST API base path the connector appends to `WORDPRESS_BASE_URL`. The default targets WordPress core wp/v2 endpoints. See [WordPress REST API routes and endpoints](https://developer.wordpress.org/rest-api/extending-the-rest-api/routes-and-endpoints/).  |
| `WORDPRESS_REQUEST_TIMEOUT` | number | No | `10` | A number of seconds | Sets how long the WordPress connector waits for each WordPress REST API response during indexing. |
| `WORDPRESS_PAGE_SIZE` | integer | No | `100` | An integer from 1 through 100. | Sets how many items the connector requests on each WordPress REST page. |
| `WORDPRESS_COLLECTIONS` | array of strings | No | `["posts","pages"]` | A JSON array of post type REST bases | Lists the post types the connector retrieves. Each REST base must exist under the configured `WORDPRESS_API_PATH`, such as `posts`, `pages`, or a custom post type exposed in the REST API. |
| `WORDPRESS_PROFILE` | string | No | `default` | `default`, `doc_landscape` | Selects the connector profile. `default` fits a standard WordPress site. `doc_landscape` is an example profile for one live WordPress site. |

## Retrieval

Search combines vector results and BM25 results, then reranks them. These settings control the candidate counts,
the fusion constant, the chunk file used for BM25, and the score cutoff.

| Setting | Type | Required | Default | Accepted values | Description |
| --- | --- | --- | --- | --- | --- |
| `LEXICAL_CORPUS_PATH` | path | No | `data/wordpress-chunks.json` | A readable JSON file with at least one valid chunk | Sets the path to the retrieval-ready chunk file used to build the BM25 index. The default matches the WordPress indexing command's default chunk output. The API reads this file when it starts and rejects a missing, unreadable, malformed, invalid, or empty file. |
| `RETRIEVAL_VECTOR_CANDIDATE_DEPTH` | integer | No | `20` | An integer of at least 1 | Sets the maximum number of vector retrieval candidates sent to reciprocal rank fusion. |
| `RETRIEVAL_LEXICAL_CANDIDATE_DEPTH` | integer | No | `20` | An integer of at least 1 | Sets the maximum number of BM25 lexical retrieval candidates sent to reciprocal rank fusion. |
| `RETRIEVAL_FUSED_CANDIDATE_DEPTH` | integer | No | `20` | An integer of at least 1 | Sets how many fused candidates the pipeline sends to the reranker. |
| `RETRIEVAL_RRF_K` | integer | No | `60` | An integer of at least 1 | Sets the ranking constant used by reciprocal rank fusion (RRF) when combining vector and lexical results. |
| `RETRIEVAL_SUPPORT_CUTOFF` | number | No | `0.70` | A number from 0 through 1 | Sets the support gate. After reranking, the retrieval service returns no results when the highest rerank score is below this cutoff. |

## Reranking

After fusion, a reranker reorders the candidates. These settings choose that provider and model.

| Setting | Type | Required | Default | Accepted values | Suggested description |
| --- | --- | --- | --- | --- | --- |
| `RERANKING_PROVIDER` | string | No | `voyage` | `voyage` | Selects the reranking provider. `voyage` is the only supported value. |
| `RERANKING_MODEL` | string | No | `rerank-2.5` | A Voyage reranking model name | Selects the Voyage model used to rerank fused retrieval candidates. |

## Answer generation

Answer requests send retrieved chunks to a language model. These settings turn that step on or off and
choose the model, the reasoning effort, the context and output limits, and the API key.

| Setting | Type | Required | Default | Accepted values | Suggested description |
| --- | --- | --- | --- | --- | --- |
| `GENERATION_ENABLED` | boolean | No | `true` | `true`, `false` | Turns answer generation on or off. `true` requires `OPENAI_API_KEY` and the other answer-generation settings when the API starts. `false` lets the API start and serve search without an OpenAI key. `POST /v1/answer` then returns `503` with `answer_unavailable`. |
| `GENERATION_PROVIDER` | string | No | `openai` | `openai` | Selects the language model provider used for answer generation. `openai` is the only supported value. |
| `GENERATION_MODEL` | string | No | `gpt-5.6-terra` | A supported OpenAI model name | Selects the OpenAI model used to generate grounded answers. |
| `GENERATION_REASONING_EFFORT` | string | No | `low` | `none`, `low`, `medium`, `high`, `xhigh`, `max` | Sets the reasoning effort requested from the OpenAI model. |
| `GENERATION_CONTEXT_BUDGET_TOKENS` | integer | No | `8000` | An integer of at least 1 | Sets the maximum number of retrieved-evidence tokens the service can include in the model context. The service keeps whole chunks in ranked order and doesn't split a chunk to fit the budget. |
| `GENERATION_MAX_OUTPUT_TOKENS` | integer | No | `1000` | An integer of at least 1 | Sets the maximum number of tokens allowed for the generated answer. |
| `OPENAI_API_KEY` | string | Yes, when `GENERATION_ENABLED` is `true` | none | A non-empty OpenAI API key | Authenticates OpenAI requests for answer generation. Required before startup when answer generation is on. Leave it unset when `GENERATION_ENABLED` is `false`. |

## WordPress client

The WordPress client calls the Python service from PHP. Define these constants in `wp-config.php`.

| Setting | Type | Required | Default | Accepted values | Suggested description |
| --- | --- | --- | --- | --- | --- |
| `RAG_SERVICE_API_BASE_URL` | PHP string constant | Yes, when using the WordPress client | none | The Python RAG Service base URL | Sets the base URL the WordPress client uses to call the Python RAG Service API. Define it in `wp-config.php`. |
| `RAG_SERVICE_API_KEY` | PHP string constant | Yes, when using the WordPress client | none | The same value configured for `RAG_API_KEY` | Sets the API key the WordPress client sends in the `X-API-Key` header. It must match the Python service's `RAG_API_KEY`. |

## Constraints and notes

- The process reads environment variables and `.env` before it accepts traffic.
A value of the wrong type, an unsupported provider, or an unreadable `.env` line stops the process.
The diagnostic names the setting, or the `.env` line when the process can't read that line, and it states the correction.
It doesn't include the supplied value, the settings dictionary, or the parser exception.
Missing credentials and a missing chunk file don't prevent importing the application or generating OpenAPI.
Those gaps fail the later startup check. Invalid values aren't replaced with defaults.
- When the API process starts, it checks local settings and the chunk file at `LEXICAL_CORPUS_PATH`.
The check covers `RAG_API_KEY`, `VOYAGE_API_KEY`, and the supported providers.
It also covers model names, `QDRANT_URL`, `QDRANT_COLLECTION`, and the numeric retrieval limits.
When answer generation is on, it checks the OpenAI key and the token budgets too.
A failing check names the setting or file to correct.
The log doesn't include setting values, credentials, chunk text, or the supplied `QDRANT_URL`.
- That startup check doesn't call Voyage, OpenAI, Qdrant, or WordPress. A process that stays up has
valid local configuration. It doesn't show that those services are reachable. `GET /health` reports
that the process is running.
- `QDRANT_API_KEY` can be empty for a local Qdrant instance that doesn't require a key. Startup
doesn't require it. Indexing requires `WORDPRESS_BASE_URL`. The API can start and serve an existing
index when that value is empty.
- `GENERATION_ENABLED` defaults to `true`. Set it to `false` for search without answer generation.
The API can then start without `OPENAI_API_KEY`. An authenticated, valid `POST /v1/answer` returns
`503` with `answer_unavailable`, and the API log uses `reason=generation_disabled`.
- `EMBEDDING_DIMENSION` has to match the configured embedding model's output. Qdrant stores vectors at
that size. After changing the embedding model, embedding dimension, chunking rules, or chunk payload
structure, run a full index rebuild. See [Index WordPress content](/docs/index-content/index-wordpress-content).
- `RETRIEVAL_SUPPORT_CUTOFF` applies to the highest rerank score for the query, not to each result.
Re-evaluate it when the indexed content, embedding model, reranking model, or chunking rules change.
- `RAG_SERVICE_API_KEY` and `RAG_API_KEY` are the same secret in two places.
The WordPress client doesn't copy one value to the other.
