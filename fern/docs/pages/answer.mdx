---
title: Answer
description: Retrieve documentation and generate a grounded answer with validated citations.
---

`POST /v1/answer` uses the same hybrid retrieval pipeline as Search, then generates a grounded answer from the selected evidence.

Retrieved chunks are passed to the answer-generation service, which assembles the model context, generates a structured answer, validates citations, and determines whether the available evidence is sufficient.

## Request

```json
{
  "query": "Why does inconsistent terminology cause retrieval failures?",
  "filters": {
    "source": "wordpress"
  }
}
```

- `query` is required. Empty or whitespace-only questions are rejected.
- `filters` is optional and uses the same keys as Search: `document_id`, `source`, `source_id`, and `content_type`.
- The answer endpoint does not accept a retrieval `limit`. Retrieval depth is controlled internally by the service.

## Successful response

A supported question returns `200 OK` with an `answer`, validated `sources`, and `sufficient_evidence: true`. Only sources whose citations were validated are returned.

If the indexed documentation does not provide enough evidence, the endpoint still returns `200 OK`, with an empty `sources` array and `sufficient_evidence: false`. That includes queries rejected by the retrieval support gate and questions the language model cannot answer from the retrieved context.

See the [API Reference](/reference/answer) for the full request and response schemas.

## Errors

| Status | Code | When |
|---|---|---|
| `401` | `authentication_failed` | The API key is missing or incorrect. |
| `422` | `validation_error` | The request does not match the public schema. |
| `503` | `authentication_unavailable` | `RAG_API_KEY` is not configured on the server. |
| `503` | `answer_unavailable` | Retrieval or answer generation cannot complete the request. |
