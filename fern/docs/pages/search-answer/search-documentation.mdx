Use `POST /v1/search` to retrieve ranked documentation for a natural-language query.
The endpoint runs hybrid retrieval and returns the selected chunks as search results.

The examples call a service at `http://127.0.0.1:8000`.
See [Quickstart](/docs/get-started/quickstart) if that service isn't running yet.

## Prerequisites

- **[Index WordPress content](/docs/index-content/index-wordpress-content)**: Build the index that `POST /v1/search` retrieves.
- **[Authentication](/docs/get-started/authentication)**: Set `RAG_API_KEY` and send that value in the `X-API-Key` header.

## Send a search request

Send `POST /v1/search` with `Content-Type: application/json` and your API key.
The body needs a `query` string. The service trims leading and trailing whitespace, and it rejects an empty query.

<CodeBlocks>
```bash curl
curl -s -X POST http://127.0.0.1:8000/v1/search \
  -H "Content-Type: application/json" \
  -H "X-API-Key: your-long-random-api-key" \
  -d '{"query": "How does metadata improve retrieval?"}' \
  | python -m json.tool
```

```python Python
import json
from urllib.request import Request, urlopen

body = json.dumps({
    "query": "How does metadata improve retrieval?",
}).encode()

request = Request(
    "http://127.0.0.1:8000/v1/search",
    data=body,
    headers={
        "Content-Type": "application/json",
        "X-API-Key": "your-long-random-api-key",
    },
    method="POST",
)

with urlopen(request) as response:
    payload = json.loads(response.read().decode())
    print(json.dumps(payload, indent=2))

```

</CodeBlocks>

A successful search returns `200`. The body echoes `query` and includes a `results` list.
The Python example prints that body only when the status is `200`. For any other status,
the example stops with an error and doesn't print the body.

## Narrow results with filters and a limit

Add `filters` when you want retrieval to consider only chunks with matching metadata.
Add `limit` to set the maximum number of search results. The default is `5`, and the value has to be at least `1`.

Supported filters are `document_id`, `source`, `source_id`, and `content_type`.
Each value is one non-empty string, or a list of non-empty strings.
A list matches a chunk when the chunk's value is one of those strings.
When you set more than one filter, a chunk has to match every filter.

For a WordPress index, `source` is `wordpress` and `source_id` is the WordPress record ID.
`content_type` uses the WordPress post type such as `page` or `post`; custom post types keep their WordPress type value.
`document_id` uses the form `wordpress:{type}:{id}`, such as `wordpress:page:1`.

<CodeBlocks>
```bash curl
curl -s -X POST http://127.0.0.1:8000/v1/search \
  -H "Content-Type: application/json" \
  -H "X-API-Key: your-long-random-api-key" \
  -d '{
    "query": "How does metadata improve retrieval?",
    "filters": {
      "source": "wordpress",
      "content_type": "page"
    },
    "limit": 5
  }' \
  | python -m json.tool
```

```python Python
import json
from urllib.request import Request, urlopen

body = json.dumps({
    "query": "How does metadata improve retrieval?",
    "filters": {
        "source": "wordpress",
        "content_type": "page",
    },
    "limit": 5,
}).encode()

request = Request(
    "http://127.0.0.1:8000/v1/search",
    data=body,
    headers={
        "Content-Type": "application/json",
        "X-API-Key": "your-long-random-api-key",
    },
    method="POST",
)

with urlopen(request) as response:
    payload = json.loads(response.read().decode())
    print(json.dumps(payload, indent=2))

```

</CodeBlocks>

To match either pages or posts, set `content_type` to `["page", "post"]`.
An unknown filter name, an empty filter value, a `limit` below `1`, or an unexpected field returns `422` with `validation_error`.
See [Search API](api:POST/reference/search) for the request schema.

## Use the search results

A `200` response lists search results in reranked order. Each result is one retrieved chunk.
Titles, excerpts, and URLs come from your index. This sample shows the response shape:

```json
{
  "query": "How does metadata improve retrieval?",
  "results": [
    {
      "chunk_id": "wordpress:page:1:chunk:v1:<sha256>",
      "document_id": "wordpress:page:1",
      "title": "Metadata Strategy",
      "heading_path": ["Metadata filtering"],
      "anchor": "metadata-filtering",
      "excerpt": "Metadata can narrow the documents considered during retrieval.",
      "url": "https://example.test/metadata",
      "score": 0.91
    }
  ]
}
```

A real `chunk_id` is `{document_id}:chunk:v1:` followed by a content hash. `<sha256>` stands in for that hash.

Use `title`, `heading_path`, and `excerpt` when you display the passage.
`url` is the source document's URL. `anchor` is the heading anchor, and it's `null` when the chunk has no anchor.
`chunk_id` identifies the chunk, and `document_id` identifies its document.
`score` is the rerank score for this query. The retrieval service reranks the fused candidates when it handles the request and returns that score.

See [Search API](api:POST/reference/search) for the response schema.

## Handle no relevant results

When the highest rerank score is below the support cutoff, `POST /v1/search` returns `200` and `results` is empty.
Treat that body as no relevant results. A query the index can't support returns this shape:

```json
{
  "query": "What is the capital of Mars?",
  "results": []
}
```

The support gate uses `RETRIEVAL_SUPPORT_CUTOFF`, which defaults to `0.70`.
See [Configuration reference](/docs/reference/configuration-reference) to change that cutoff.
Your client can show the ranked chunks, or an empty state when `results` is empty.

## Troubleshooting

Check the terminal where you started the API with uvicorn. The service logs the failed operation and a diagnostic reason there.

### 401 `authentication_failed`

Send an `X-API-Key` that matches the service's `RAG_API_KEY`.
A missing or wrong key makes `POST /v1/search` return `401` with `authentication_failed`.
See [Authentication](/docs/get-started/authentication) for the API key checks.

### 422 `validation_error`

Check the query, the supported filters, and `limit`.
`POST /v1/search` returns `422` with `validation_error` when the request doesn't match the schema.

### 503 `authentication_unavailable`

Set `RAG_API_KEY` in the service's `.env`, then restart the API.
`POST /v1/search` returns `503` with `authentication_unavailable` when that key isn't set.

### 503 `retrieval_unavailable`

Check the configuration, credentials, and availability of the retrieval dependencies.
`POST /v1/search` returns `503` with `retrieval_unavailable` when one of those dependencies can't complete the search.
See [Configuration reference](/docs/reference/configuration-reference) for those settings.
