Look up the error responses from `POST /v1/search` and `POST /v1/answer` on the Python RAG Service.
Each entry lists the HTTP status, the `error.code` value, the public `error.message`, and the
condition that produces it.

This page covers search and answer errors. For the documented `GET /health` response, see [Health check](api:GET/reference/health).

## Error response

Errors on this page share a JSON structure. This example shows an authentication failure:

<Markdown src="/docs/snippets/code/authentication-failed-error-body.mdx" />

| Field | What it contains |
| --- | --- |
| `error.code` | Stable identifier for the failure. Branch on this value. |
| `error.message` | Public summary. For the codes on this page, the summary is fixed. |
| `error.details` | Field problems for `validation_error`. An empty list for the other codes. |
| `error.details[].field` | Dotted request path, such as `limit` or `filters.site_id`. Null when the failure isn't tied to one field. |
| `error.details[].message` | Validation message for that field. |

Use `error.code` and `error.details[].field` when handling validation failures programmatically.
Treat `error.details[].message` as explanatory text.

`details` can contain more than one entry. Read `error.code` when the status is 500 or 503.
Search can return `authentication_unavailable` or `retrieval_unavailable` for HTTP 503.
Both routes can return `configuration_error` or `internal_error` for HTTP 500.

## Error codes

| Status | `code` | `message` | Routes |
| --- | --- | --- | --- |
| 401 | `authentication_failed` | A valid API key is required. | `POST /v1/search`, `POST /v1/answer` |
| 413 | `request_too_large` | The request body is too large. | `POST /v1/search`, `POST /v1/answer` |
| 422 | `validation_error` | Request validation failed. | `POST /v1/search`, `POST /v1/answer` |
| 503 | `authentication_unavailable` | API authentication is temporarily unavailable. | `POST /v1/search`, `POST /v1/answer` |
| 503 | `retrieval_unavailable` | Search is temporarily unavailable. | `POST /v1/search` |
| 503 | `answer_unavailable` | Answer generation is temporarily unavailable. | `POST /v1/answer` |
| 500 | `configuration_error` | The service configuration is invalid. | `POST /v1/search`, `POST /v1/answer` |
| 500 | `internal_error` | The service couldn't complete the request. | `POST /v1/search`, `POST /v1/answer` |

The search route's OpenAPI example for HTTP 503 is `retrieval_unavailable`. The answer route's
OpenAPI example for HTTP 503 is `answer_unavailable`. A missing `RAG_API_KEY` still returns
`authentication_unavailable` on both routes.

## Validation errors

`validation_error` means the JSON request body doesn't match the endpoint's schema. `error.details` lists each problem.
Fields not defined in the schema are rejected.

Before checking text length, the service removes leading and trailing whitespace from `query` and each filter value.
Values containing only whitespace are rejected because they're empty after trimming.

| Field | Accepted values |
| --- | --- |
| `query` | 1–2,000 characters after trimming. |
| Each filter value | 1–256 characters after trimming. |
| Filter list | 1–50 values. |
| Search `limit` | An integer from 1–20. Default: `5`. |

Text length is measured in Unicode code points. For example, `é` stored as a single code point counts as one character.
A letter followed by a separate combining accent counts as two.

For example, sending `limit: 0` to `POST /v1/search` returns:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Request validation failed.",
    "details": [
      {
        "field": "limit",
        "message": "Input should be greater than or equal to 1"
      }
    ]
  }
}
```

`POST /v1/answer` doesn't accept `limit`. Sending it produces this body:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Request validation failed.",
    "details": [
      {
        "field": "limit",
        "message": "Extra inputs aren't permitted"
      }
    ]
  }
}
```

An unknown filter name uses a dotted `field`, such as `filters.site_id`. Supported filter names
are `document_id`, `source`, `source_id`, and `content_type`. See
[Search indexed docs](api:POST/reference/search) for the search schema and
[Generate grounded answer](api:POST/reference/answer) for the answer schema.

## Request body too large

Both `POST /v1/search` and `POST /v1/answer` return HTTP 413 with `request_too_large` when the request body exceeds 65,536 bytes (64 KiB).
The message is `The request body is too large.` `details` is empty.

The service counts the bytes it receives before it parses JSON. Omitting `Content-Length`, sending
a header that doesn't match the body, or splitting the body into chunks uses that same count. An
oversized body doesn't start retrieval or answer generation.

A body within the size limit can still fail field  validation. These limits don't restrict how many
requests a client can send, and they don't cap spending on Voyage, Qdrant, or OpenAI.

## Authentication errors

Both routes check `X-API-Key` before retrieval or answer generation.

### `401` `authentication_failed`

`authentication_failed` is HTTP 401. The header is missing, or its value doesn't match the
service's `RAG_API_KEY`. The body is the example under [Error response](#error-response). `details` is empty.

### `503` `authentication_unavailable`

`authentication_unavailable` is HTTP 503. `RAG_API_KEY` isn't set on the service, so the routes
can't authenticate a client. Startup also stops when that key is blank. The route returns this
response if it receives a request while the key is unset.

The message is `API authentication is temporarily unavailable.` `details` is empty. The service logs
`operation=authentication` and `reason=missing_service_api_key`. That log line isn't part of the response.

See [Authentication](/docs/get-started/authentication) to set the key and send the header.

## Retrieval errors

### `503` `retrieval_unavailable`

`POST /v1/search` returns this error when a retrieval provider is temporarily unavailable. Causes include:

- Connection failures.
- Timeouts.
- Rate limits.
- Provider server errors.

**Response:** The message is `Search is temporarily unavailable.` `details` is empty. The response doesn't include
the underlying exception.

**Server log:** The service logs `operation=retrieval` and `reason=retrieval_dependency_failed`.

`VOYAGE_TIMEOUT_SECONDS` and `QDRANT_TIMEOUT_SECONDS` control individual provider calls, not the duration of the whole
search request. See [Timeouts and retries](/docs/reference/timeouts-and-retries).

Retrieval failures on `POST /v1/answer` return `answer_unavailable` instead.

### Empty search results

An empty `results` list returns HTTP 200, including when the support gate rejects the retrieved results. This is a
completed request, not an API error.

See [Search indexed docs](api:POST/reference/search) for the response format.

## Answer-generation errors

`answer_unavailable` is HTTP 503 from `POST /v1/answer` when the answer workflow can't finish.
The message is `Answer generation is temporarily unavailable.` `details` is empty. The same
public body covers every cause below. The response doesn't include provider exception text.

The route returns this code when:

- `GENERATION_ENABLED` is `false`. The service logs `operation=generation` and `reason=generation_disabled`. It doesn't build the answer generator or call providers.
- Retrieval hits a temporary provider failure.
- The language-model request hits a connection failure, timeout, rate limit, or provider server error. `OPENAI_TIMEOUT_SECONDS` bounds each OpenAI attempt. It doesn't set a deadline for the whole answer request.
- The language model refuses the request or returns no usable structured answer.
- The formatted context for the highest-ranked chunk exceeds the configured token budget.
- Citation validation fails.

The service logs `operation` and `reason` for that cause. Those values stay on the API server.

An answer with `sufficient_evidence` set to false is HTTP 200, and `sources` is empty. See
[Generate grounded answer](api:POST/reference/answer).

## Configuration errors

`configuration_error` is HTTP 500 when a known configuration problem occurs while the service handles a request.

### Causes

Request-time causes include:

- A missing `OPENAI_API_KEY`.
- An unreadable chunk file.
- An unrecognized generation model.
- A provider response with HTTP 400, 401, 403, 404, or 422.

### Response and server diagnostics

**Response:** The message is `The service configuration is invalid.` `details` is empty. The response doesn't include
setting values or the provider exception.

**Server log:** The reason identifies the cause, and the diagnostic names the setting to check. A missing `OPENAI_API_KEY`
uses `reason=missing_provider_api_key`.

### Startup failures

Configuration problems detected during startup stop the process. They don't return this API response.

When `GENERATION_ENABLED` is `true`, startup also requires `OPENAI_API_KEY`.

## Unexpected errors

`internal_error` is HTTP 500. The service hit a programming error. The message is
`The service couldn't complete the request.` `details` is empty. The log uses
`operation=request` and `reason=unexpected_failure`.

The response and the log omit the exception text, the traceback, and the request body.

## Constraints and notes

### Where to find server logs

Each handled failure that produces HTTP 500 or 503 writes one diagnostic line on the API server.

- **Local development:** Check the terminal where you started Uvicorn.
- **Hosted deployment:** Check your hosting platform's application logs.

Each line includes the time, severity, logger name, operation, and reason. HTTP 401, 413, and 422 responses don't
write these diagnostic failure logs.

### Log level

`LOG_LEVEL` accepts `DEBUG`, `INFO`, `WARNING`, `ERROR`, or `CRITICAL`. It controls the severity level for `rag_service` loggers.

It doesn't change Uvicorn's logs or enable debug logging for provider SDKs or HTTP clients.
See [Configuration reference](/docs/reference/configuration-reference).

### Connection failures

A client that can't connect to the service receives no API response. The error codes on this page apply only after the
service accepts a request.
